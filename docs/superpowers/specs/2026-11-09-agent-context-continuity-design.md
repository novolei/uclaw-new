## 1. 意图

用户原话："长对话后经常忘记前面的内容"。目标是让 agent 在长对话中**不丢失上下文**，并借此全面打磨提示词体系、缓存命中和 token 使用，参照 Anthropic / Claude Code 的上下文工程实践。

用户明确的优先级：
- 两类信息都要保留：**用户说过的要求和决定**，以及 **agent 自己做过的事**；其中**读过的文件和改过的代码最重要**。
- **验收标准**：长对话中能准确说出之前改过哪些文件、各改了什么（含跨压缩、跨重启）。
- **成本**：完整历史会让长对话的 token 用量逐步上升，用户接受，但以压缩阈值控制上限——**默认 128K token，设置里可调**。

## 3. 参考实践（Anthropic，2025-09 至 2026-04 的官方文档与工程博客）

- **上下文工程**（anthropic.com/engineering/effective-context-engineering-for-ai-agents）：用最小的高信号 token 集合；上下文越长召回越差（context rot）；按需检索、留引用而非全文；结构化笔记；长对话用压缩。
- **Claude Code 压缩**（code.claude.com/docs/en/context-window 等）：**不用滑动窗口**，保留完整历史直到阈值；压缩后保留摘要，并**重新载入**系统提示词、CLAUDE.md/记忆、计划文件、**最多 5 个最近读写过的文件**（单个 >5K token 只给路径）、调用过的 skill 正文（≤5K/个，总 ≤25K）、后台任务提醒。
- **缓存安全的压缩**（claude.dev 博客 "Prompt caching is everything"，2026-04-30）：压缩调用复用主对话完全相同的 system / tools / messages，把压缩指令作为最后一条用户消息追加 → 读到已缓存前缀。
- **上下文编辑**（platform.claude.com context-editing）：默认在 100K 时清理旧工具结果，保留最近 3 组调用/结果，被清理的结果替换为占位文字；`clear_at_least` 让每次清理值回缓存失效的代价。
- **服务端压缩 API**：默认 150K 触发；按需模式由调用方选切分点，下一次请求为"摘要块 + 原文保留的近期轮次 + 新消息"；**绝不在工具调用与其结果之间切分**。
- **缓存原则**（platform.claude.com prompt-caching）：前缀精确匹配；顺序 tools → system → messages；系统提示词冻结，动态内容放在消息里；**每轮提醒注入后保留在原处、不删除**（删除即改写历史）；工具定义确定性排序；用 usage 字段持续验证。
- **提示词规范**（claude-prompting-best-practices）：合适的抽象高度；说明原因而非大写强调；分段结构清晰；**若会压缩，应在提示词中告知模型**，否则它会在上下文将满时提前收尾。

DeepSeek 的自动前缀缓存同样是精确前缀匹配，以上缓存原则直接适用；由于不能放断点，"只追加、不改写"更为关键。

## 4. 目标 / 非目标 / 反目标

**目标**
- G1 长对话不丢失：历史完整保留直到压缩阈值；压缩后的摘要真正进入后续提示词。
- G2 文件工作集：读过、改过的文件在任意时刻（含压缩后、重启后）都可准确说出，改动内容可追溯。
- G3 缓存与 token：历史只追加；系统提示词冻结；每轮未命中 token 显著下降；短对话速度与费用不回退。
- G4 提示词体系按 Claude 规范精简打磨；吸收 T3（skills 清单限量 + 相关性提示）。

**非目标**（本项目不做）
- T4（反思/用户画像）、T5（daydream）、T6（skills 市场）。
- Chat 模式（`send_message`）——Agent 模式完成后另立项跟进。
- 跨会话长期记忆体系的重构（bucket_seal / memory_graph 保持现状，只改"召回查询"和"注入方式"）。

**反目标**（即使技术上可行也算失败）
- 界面上的对话记录因存储结构变化而显示异常或丢失。
- 依赖某一家服务商的专属接口（服务端压缩、context editing API 等）才能工作。
- 短对话的首 token 延迟或费用相对当前 main 变差（以 `scripts/bench/` 实测为准）。

## 6. 设计

### 6.1 提示词分层（从前到后稳定性递减）

```
[tools]                       确定性排序，会话内不增删
[system]                      冻结：基础/模式/人设/基线 + 限量且确定性排序的 skills 清单
                              + "关于上下文压缩"说明；会话内字节不变
[会话固定块] (messages 开头)    最近一次压缩的摘要 + 文件工作集 + 当前计划 + 最近改过的文件内容
                              —— 只在压缩时重写（重写本身就是缓存断点，可接受）
[完整历史]                     只追加：每轮 = 用户消息(带当轮动态块原文) + 助手文字/工具调用/工具结果
[本轮新内容]                   新用户消息 + 本轮动态块
```

规则：任何在 `[system]` 中会随轮次变化的内容都必须移出或固定（D9）：
- gene 块 → 移到本轮动态块。
- 项目规则（`.uclawrules` 等）→ 会话开始时解析一次并固定；会话中规则文件变化时以"规则已更新"提醒追加到动态块，不改 system。
- skills 清单 → 见 §6.6。
- 计划建议提示（plan-suggest hint）→ 移到动态块。

### 6.2 完整转录持久化（解决 D2、D8）

新增**只追加的转录表**（迁移取下一个空闲 V 号，当前为 V63，实施时以 `CONTEXT.md` 迁移登记表为准）：

- `agent_transcript(session_id, seq, kind, content_json, est_tokens, created_at, turn_id)`
  - `kind`：`user` / `assistant` / `tool_use` / `tool_result` / `compaction_summary` / `session_block` 等。
  - `content_json`：**实际发给模型的内容块**（用户消息含当轮动态块原文；工具结果为当时的版本或清理后的占位，见 §6.4）。
- 重放规则：下一轮直接按 `seq` 读出并原样还原为 `ChatMessage` 内容块，保证字节一致。
- `agent_messages` 保持现状，继续供界面显示（反目标：界面不受影响）。
- 旧会话（升级前，无转录行）：回退到现有 `agent_messages` 文本重放 + 当前窗口逻辑，仅对新会话或首次产生转录行之后启用新路径。
- 推理（thinking/reasoning）是否重放：**作者倾向不重放**（DeepSeek 推理内容不要求回传；Claude 新模型要求原样回传 thinking 块——若以后对 Claude 启用 thinking，需按服务商策略决定），实现时以服务商要求为准。

### 6.3 历史策略与压缩触发（解决 D1、D4、D5）

- Agent 路径**移除** `history_budget_window` 头尾截断。
- 每次调用前估算**完整请求**的 token：tools + system + 会话固定块 + 历史 + 本轮内容（修正 D4 的估算口径）。
- 达到**压缩阈值**（设置项，默认 128K；上限为模型窗口减去输出与安全余量）时执行压缩（§6.5）。
- 硬截断保留为最后防线，但**不得丢弃本轮用户消息与会话固定块**；触发时记录警告。
- 现有 `compression_threshold` 配置或删除、或接到新阈值上，避免两个口径并存。

### 6.4 旧工具结果清理（解决 D11，参照 context editing）

- 保留**最近 3 组**工具调用/结果原文（可配置）。
- 更早的工具结果替换为一行占位，保留可追溯线索，例如：
  `[已清理的工具结果：read_file src/foo.rs 第 1–200 行（约 3.1K token）——如需内容请重新读取]`
  `[已清理的工具结果：grep "foo" 于 src/，命中 14 处]`
- **批量清理**：只有当"可清理的工具结果总量"超过一个下限（建议 20K token，可配置）时一次性清理，使每次缓存失效值得（对应官方 `clear_at_least`）。
- 清理结果**写回转录表**（即更新该行的 `content_json` 为占位版本），此后所有轮次重放的都是占位版本，保证之后前缀稳定。这是一次有意的、批量的历史改写。
- 文件写入/编辑类工具的**结果**可清理，但其改动由文件工作集（§6.5）记录，不会丢失。

### 6.5 文件工作集与压缩（解决 D3、D6、D7；满足 G2）

**文件工作集（持久化）**
- 将 `SessionFileOps` 扩展并按会话持久化（新表或会话级 JSON，实施时定）。每个文件记录：路径、读取过的范围、最后读取时间；写入/编辑次数、每次改动的摘要（工具参数中的 old/new 片段或 diff，截断到合理长度）、最后修改时间、当前是否仍存在。
- 由文件类工具（read/write/edit/patch/bash 中可识别的文件操作）在执行后更新。
- 渲染为 `<file_working_set>` 块：改过的文件在前（含改动摘要），读过的文件在后（只列路径与范围）。

**压缩流程**（达到阈值时，在一轮的边界执行；不在工具调用与结果之间切分）
1. 选切分点：保留最近若干轮原文（默认最近约 20K token 或最近 3 轮，取大者，可配置），其余进入摘要。
2. **复用前缀的摘要调用**：请求 = 与主对话相同的 tools + system + 历史，末尾追加一条压缩指令 → 读已缓存前缀。
3. 摘要采用结构化模板：用户的主要请求与**全部用户消息要点**（要求、决定、纠正，尽量保留原话）、关键技术决定、遇到的错误及解决、未完成事项、当前进展与下一步。目标长度可配置（默认约 2–4K token，现有 `TARGET_FOLD_TOKENS = 800` 偏小）。
4. 生成新的**会话固定块**：摘要 + `<file_working_set>` + 当前计划正文 + **最近改过的最多 5 个文件的当前内容**（单个超过 5K token 只给路径，提示需要时读取）。
5. 写入转录表：插入 `compaction_summary` / `session_block` 行并标记被覆盖的旧行（重放时跳过），保证重启后同样生效。
6. 现有 `StructuredFold` / 增量 fold 逻辑可复用为摘要生成器；但**必须让结果进入提示词**（D3）。

**计划状态（D6）**：当前计划正文（plan 文件或 plan 工具状态）在会话固定块中渲染；未压缩前也可在动态块中以"计划已更新"提醒追加。

### 6.6 动态块、记忆注入与 skills（解决 D8、D9、D10；吸收 T3）

**动态块随用户消息持久化**：每轮的动态块原文写入转录表的该用户消息，后续轮次原样重放（只追加，不再删除）。

**记忆只注入变化部分**
- 会话内第一次（以及每次压缩之后）注入完整 `<memory_context>`。
- 之后各轮：计算本轮召回结果与"自上次完整注入以来已出现在转录中的记忆行"的差集，只注入新增/变化的行，形如 `<memory_update>`；对已失效的条目可附简短 "- 已过时: …"。
- 预期：实测中记忆上下文约 5.3K token 且各轮几乎相同，改后每轮未命中 token 应从约 6.5K 降到约 1K 量级（以 bench 实测为准）。

**记忆召回查询（D10）**：查询文本 = 本轮用户消息 + 最近 2–3 条用户消息摘要（或会话固定块中的当前目标）；修正硬编码的 `"default"` space，使用会话实际 space。

**skills 清单（T3，参照 uclaw-pi 070c1bcc / e4bc305c / d5cbfe23）**
- 系统提示词中的清单改为 `build_skills_manifest` 生成的**限量**清单（`SYSTEM_PROMPT_MANIFEST_MAX_TOKENS = 1500`、`_MAX_ENTRIES = 200`），**会话内确定性排序且不变**（例如按会话开始时的使用度快照排序）；不再因 `skill_search` 使用而隐藏。
- "本轮相关"排序（词法 #106 + 语义 #111）**不改系统提示词**，而是在动态块中追加 `<relevant_skills>`（Top N，名称 + 一句话说明）。语义部分按审计建议直接复用 `bucket_seal_embedder` + `skill_embedding` + `cosine_similarity`，带期限（≤400 ms，超时只用词法）。
- 需同时验证内置 skill 与插件 skill 仍可被发现（`load_skill` / `skill_search`）。

### 6.7 系统提示词打磨（G4）

- 按 Claude 提示词规范审查基础提示词、模式提示词、基线块：去掉大写强调与命令式堆叠，说明原因；分段结构清晰；删除过时或互相冲突的规则。可用 `/claude-api prompt-audit` 生成审计报告与建议 diff 作为起点。
- 新增一段"关于上下文"：说明会自动压缩、压缩后会提供摘要/文件工作集/计划/最近文件；不要因上下文接近上限而提前结束；需要旧内容时重新读取文件。
- 改动以验收测试（§7）与 bench 结果为准，避免凭感觉改动。

### 6.9 生命周期与边界情况（审阅后补充）

**适用范围（作者决定）**：新行为只对交互式 `send_agent_message` 会话启用，通过传给 `run_agentic_loop` 的配置开关控制。`symphony_graph`、`headless`、`regular_task`、teams、以及 `tauri_commands.rs:1403` 等其他调用方保持现状（它们没有转录表），只需回归测试确认未受影响。

**写入时机与轮内压缩（作者决定）**
- 转录行**按迭代写入**：一次迭代结束、工具执行完毕后，把该迭代的助手消息（文字 + 工具调用）与对应的全部工具结果**在同一事务内**写入，保证任何时候都不存在"有调用、无结果"的行。
- 工具执行过程中被取消/崩溃：为未完成的调用补写合成结果（如 `[工具调用已取消]`），保持调用/结果成对；与阶段 0 的"失败轮次保存回复"一致。
- 压缩可以在**一轮之内的迭代边界**执行（单个长工具循环也可能超过阈值）：在迭代之间、且不在工具调用与结果之间切分。先尝试工具结果批量清理；清理后仍超过阈值才压缩。硬截断只作为最后防线。

**会话中途的变化（作者决定）**
- 冻结的系统提示词按会话保存（会话开始时生成并持久化）。
- 权限模式切换、插件/MCP 开关：不重建系统提示词与工具列表，而在下一轮动态块追加一条说明（如"权限模式已切换为 X"）；工具可用性以执行时的实际校验为准。若工具集合必须变化（新增/移除工具），在下一轮重建工具列表并接受一次缓存失效。
- 切换提示词模板（`prompt_id`）或策略：重建系统提示词，接受一次缓存失效。
- 切换模型：缓存本就按模型隔离；按新模型的窗口重新校验阈值（阈值不得超过新模型窗口减余量，例如本地小模型）。若新窗口装不下当前历史，立即压缩后再发送。
- §7.C 的前缀一致性测试对以上事件发生的轮次豁免。

**`/compact`（作者决定）**：手动 `/compact` 走同一套新压缩流程（写入 `compaction_summary` / `session_block`），删除旧的独立 fold 路径，只保留一种压缩实现。

**升级前的旧会话（作者决定）**：首次在旧会话上走新路径时，把旧的 `agent_messages` 文本行**一次性导入转录表**（完整导入，**不做头尾截断**），此后所有内容只来自转录；整体同样受压缩阈值约束，超过就压缩。这样旧会话也能找回此前被截断的历史，且压缩/回退/分叉只处理一种来源，避免被压缩的旧文本在重放时重复出现。

**回退（rewind）与分叉（fork）**（`rewind_session` / `fork_agent_session`，`agent/session_tree.rs`）
- 转录表增加与 `agent_messages` 行的关联键（`turn_id` 对应用户消息行），回退/分叉时按同一个点截断或复制转录行。
- 回退点早于最近一次压缩：被压缩覆盖的旧行只做标记、不物理删除，回退时恢复这些旧行并丢弃之后的压缩摘要与会话固定块；恢复后若超过阈值，下一轮按正常流程重新压缩。
- **文件工作集不随回退/分叉回滚**（用户确认）：回退不恢复磁盘文件，因此被回退轮次中的改动仍保留在工作集里，但标记为"来自已回退的轮次，磁盘上仍保留"（渲染时单独分组或加注），让模型掌握磁盘真实状态。分叉复制工作集（含此类标记）。

### 6.10 可观测性

- 每次调用记录：完整请求估算 token、缓存命中 token（已有 `cache_read_tokens`）、是否发生压缩/清理及释放的 token。
- 每次压缩记录：切分点、摘要长度、会话固定块长度、耗时、摘要调用的缓存命中。
- `cost_store::record` 增加缓存命中字段写入（目前 `cost_records.cached_input_tokens` 恒为 0）。

## 7. 验收

**A. 长对话文件记忆（主验收，用户标准）**
- 脚本化长对话：前期修改 N 个文件（N ≥ 5，跨多个目录，含新建与删除），中间大量读取/搜索使上下文超过阈值，**至少触发一次压缩**；结尾提问"这次会话改过哪些文件、各改了什么"。要求：文件**无遗漏**，改动描述准确。
- 变体：重启应用后提问；触发两次以上压缩后提问；把阈值调到 32K 以便快速复现。
- 同时提问早期的一条用户要求，验证"用户说过的要求"同样保留。

**B. 回归（`scripts/bench/`）**
- 原 7 条消息基准：首 token、整轮耗时、费用不劣于当前 main（首 token 中位数 1.14 s，每次调用输入中位数约 27K）。
- 长对话：缓存命中率高于当前；每轮首次调用的未命中 token 显著下降（目标 ≤ 2K，实测确认）。

**C. 自动化测试**
- 重放字节一致性：同一会话连续两轮构造的请求，前一轮请求必须是后一轮请求的前缀（剔除本轮新增后逐字节相等），清理/压缩发生的轮次除外。
- 压缩：切分不拆开工具调用与结果；固定块包含摘要、文件工作集、计划；重启后重放结果一致。
- 工具结果清理：占位保留路径/范围；只在超过下限时触发。
- skills：清单限量且会话内字节不变；`<relevant_skills>` 期限内返回，超时只用词法。
- 旧会话回退路径可用。

## 9. 风险

- **首次冷启动成本**：长会话在缓存过期后再次继续，整段历史按全价处理一次；阈值越高越贵（这是用户选择 128K 默认值的取舍）。
- **重放字节不一致**：任何非确定性序列化（JSON 键序、时间格式）都会让"只追加"失效——需要 §7.C 的字节一致性测试兜底。
- **旧会话混用**：升级前的会话没有转录行，回退逻辑需要可靠，避免界面与模型看到的历史不一致。
- **Anthropic 的 thinking 块回传规则**：若以后对 Claude 模型开启 thinking 且需原样回传，转录必须保存 thinking 块；本设计的转录格式应能容纳。
- **工具结果清理是一次历史改写**：批量触发以控制频率；清理后的占位必须足以让模型知道"去哪里重新读取"。
